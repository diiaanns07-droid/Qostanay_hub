# Adal

**Локальный прокторинг: телефон, направление внимания и защита экзаменационной среды.**

Проект по кейсу №3 Qostanai Industry Hackathon. Adal анализирует камеру на ПК студента и собирает события экзамена для проверки преподавателем. Экзамен может находиться на отдельном сайте: преподаватель задаёт разрешённые адреса, а студент открывает их в экзаменационном окне Adal.

[Демонстрация и соответствие кейсу](proctoring/docs/submission/ADAL_DEMO.md) · [HTML-презентация](presentation/adal/index.html) · [Запуск](proctoring/README.md) · [Результаты интеграции](proctoring/handoffs/CLASSROOM-ACCEPTANCE/STATUS.md)

HTML-презентация открывается локально в браузере после скачивания файла. Её интерактивные сцены используют синтетические данные; для проверки работающего приложения предназначен сценарий демонстрации.

| Задача кейса | Подход Adal |
| --- | --- |
| Телефон перед экраном, подъём и возможная съёмка | YOLO11n и временные признаки положения телефона; сигнал требует проверки человеком |
| Взгляд вниз/в стороны, присутствие и второе лицо | MediaPipe, индивидуальная калибровка и длительность наблюдения |
| Защита экзаменационной среды | Ограничения экзаменационного окна Electron и подключаемый Windows helper; результат блокировки проверяется на целевом ПК |

Для компьютерного класса предусмотрена панель преподавателя: подключения по Ethernet/Wi-Fi, карточки студентов, просмотр эпизодов и клипов, команды с причиной и подтверждением выполнения. Это дополняет три обязательных блока кейса.

> **Статус: интегрированный прототип для пилота.** Управление классом проверено с настоящими сервером, клиентами и Electron на синтетических источниках. Точность CV, совместная работа реальных камеры и микрофона с Enforce и пилот на трёх физических ПК ещё требуют проверки.

## Как проходит экзамен

1. Преподаватель запускает сервер и панель на своём компьютере, создаёт класс и указывает адрес экзамена.
2. Студенты подключаются по коду класса, проходят проверку оборудования и калибровку.
3. Во время экзамена локальный CV-конвейер формирует наблюдения. Преподаватель видит состояние студентов, события и зоны внимания, открывает карточки и доступные клипы для проверки.
4. Преподаватель может временно закрыть экзаменационное окно с указанной причиной, открыть его снова и управлять проверкой микрофона. Студент видит состояние проверки и блокировки.
5. Преподаватель рассматривает события и завершает экзамен. Сигнал системы сам по себе не означает, что студент списывал.

| На компьютере преподавателя | На компьютере студента |
| --- | --- |
| Сервер класса и панель в браузере | Приложение Electron и локальный Python backend |
| Состояние класса, события, карточки и просмотр клипов | Камера, калибровка, CV-наблюдения и экзаменационное окно |
| Команды с подтверждением выполнения приложением | Видимая причина блокировки и индикаторы проверки |

Панель преподавателя открывается **на ПК сервера**. По локальной сети к нему подключаются студенческие приложения; удалённый доступ к панели с произвольного браузера сейчас не предусмотрен.

## Быстрый запуск на Windows

Нужны **Git, Python 3.12 x64 и `uv`**. На студенческих ПК дополнительно нужны **Node.js 22.12 или новее и npm**. Команды предназначены для Windows PowerShell 5.1 или PowerShell 7.

На каждом ПК получите одну и ту же версию проекта:

```powershell
git clone --branch main https://github.com/diiaanns07-droid/Qostanay_hub.git Adal
cd Adal\proctoring
```

Подготовка скачивает зависимости и выполняется заранее, пока есть интернет. Это запуск из исходников; готовый установщик и проверенный переносимый офлайн-комплект пока не опубликованы.

### ПК преподавателя

```powershell
.\packaging\prepare-windows.ps1 -BackendOnly
.\Start-Adal.ps1 -Role Teacher -CheckOnly
.\Start-Adal.ps1 -Role Teacher -Lan -Port 8765
```

Оставьте консоль открытой. На этом же ПК откройте **http://127.0.0.1:8765/**, введите PIN из консоли и создайте класс. Студентам передайте **шестизначный код класса** и LAN-адрес сервера. PIN преподавателя студентам не передаётся.

### Каждый студенческий ПК

```powershell
.\packaging\prepare-windows.ps1 -FetchModels

$server = '192.168.1.10:8765' # замените адресом ПК преподавателя
$code = Read-Host 'Шестизначный код класса'
.\Start-Adal.ps1 -Role Student -Server $server -JoinCode $code -Label PC2 -Enforce -CheckOnly
.\Start-Adal.ps1 -Role Student -Server $server -JoinCode $code -Label PC2 -Enforce
```

На следующем ПК используйте другую метку, например `PC3`. В приложении выберите **LIVE**, пройдите согласие, проверку оборудования и калибровку. SYNTHETIC предназначен для демонстрации и тестов и не является анализом реальной камеры.

`-FetchModels` загружает модели телефона и внимания. Дополнительные модели не входят в эту команду. `-CheckOnly` проверяет локальную подготовку, но не проверяет связь между ПК, код класса, устройства или фактическую блокировку Windows.

Оба типа подключения — Ethernet и Wi-Fi — используют обычную локальную сеть. ПК должны видеть друг друга; на ПК преподавателя должен быть разрешён выбранный TCP-порт в частном профиле Windows Firewall. Запускатель сам не меняет брандмауэр. На студенческом ПК не указывайте `127.0.0.1` вместо адреса преподавателя.

**Аварийный выход: Ctrl+Alt+Shift+F12.** Перед живой репетицией проверьте его на целевом ПК. Подробные действия при зависании и порядок остановки приведены в [инструкции запуска](proctoring/README.md#остановка-и-восстановление).

### Границы блокировки

- `-Enforce` запрашивает применение нативных ограничений во время экзамена. Их действие нужно подтверждать на конкретном Windows-ПК; экран блокировки приложения сам по себе этого не доказывает.
- Разрешённые сайты ограничиваются внутри экзаменационного окна Adal. Системный список разрешённых программ Windows пока не реализован.
- Обычная HTTP-форма может сохраняться при временной блокировке. Страница с WebSocket может закрываться с предупреждением о потере несохранённых ответов.
- Ctrl+Alt+Del и защищённый экран UAC не блокируются.
