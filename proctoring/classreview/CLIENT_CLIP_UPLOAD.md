# Загрузка клипа с компьютера студента — требования T03 (qorgau.class.v1)

Для разработчика, который создаёт клип на компьютере студента (модуль uplink). Сервер (T03) принимает,
проверяет, хранит и показывает клип преподавателю. Готовые примеры: `examples/upload_clip.py` (только
стандартная библиотека — можно перенести в uplink как есть) и `examples/fake_student.py` (полный поток
протокола против DEV-стенда).

## 1. Когда загружать

1. Эпизод сначала отправляется сообщением `incident` по `/ws/student` (§3.1) с тем же `incident_id`.
   `clip_available: true` — только если клип действительно можно собрать (кольцевой буфер записи содержит
   нужный интервал); иначе `false`, и преподаватель сразу видит «клип недоступен».
2. Видео передаётся **только по запросу**: сервер присылает `command {kind: "request_clip", payload: {incident_id}}`.
   Без запроса сервер отвечает `409 clip_not_requested`.
3. На каждую команду — ровно один `ack` (§3.2):
   * клип можно собрать → сразу `ack {command_id, ok: true}`, затем загрузка (`ack` нужен в пределах 10 с,
     а сборка клипа может ждать 5 с «после» эпизода);
   * клип собрать нельзя → `ack {command_id, ok: false, error_ru: "<понятная причина>"}`. Причина показывается
     преподавателю дословно («Клип недоступен: …»), он может запросить снова.
4. Если клип не пришёл за 120 с после запроса, преподаватель видит «недоступен: клип не получен»; поздняя
   загрузка всё равно принимается.

## 2. Запрос

```
POST http://<сервер>:8765/api/student/clips/{incident_id}
Authorization: Bearer <resume_token из welcome>       ← токен только в заголовке, никогда в URL
Content-Type: video/mp4                               ← или video/x-msvideo
Content-Length: <размер>
X-Qorgau-Clip-Source: live | replay | synthetic | test ← необязательно (расширение, ждёт подтверждения T01)

<байты файла целиком; не multipart, не base64>
```

Пример (Python, stdlib):

```python
from upload_clip import upload_clip, UploadFailed
data = open(clip_path, "rb").read()          # читаем ОДИН раз: повторы шлют те же байты
try:
    r = upload_clip("http://192.168.1.10:8765", resume_token, incident_id, data, source="live")
    # r == {"status": "stored"|"duplicate", "sha256": "...", "size_bytes": ..., "codec": "avc1", ...}
except UploadFailed as e:
    log(e.status, e.code, e.message_ru)       # 4xx: не повторять, исправить причину
```

Пример (curl, для ручной проверки):

```bash
curl -sS -X POST "http://127.0.0.1:8765/api/student/clips/inc-s-1-3" \
  -H "Authorization: Bearer $RESUME_TOKEN" -H "Content-Type: video/mp4" \
  -H "X-Qorgau-Clip-Source: test" --data-binary @test_clip.mp4
```

## 3. Ответы и что делать

| Код | `error.code` | Что значит | Действие клиента |
|---|---|---|---|
| 201 | — (`status: "stored"`) | клип сохранён | удалить временный файл |
| 200 | — (`status: "duplicate"`) | эти же байты уже сохранены (повтор после потерянного ответа) | считать успехом |
| 401 | `student_auth_failed` | нет/неверный `resume_token` | переподключиться (`hello` с `resume_token`), не повторять вслепую |
| 404 | `incident_not_found` | у этого студента нет такого эпизода | сначала отправить `incident`; проверить `incident_id` |
| 409 | `clip_not_requested` | преподаватель не запрашивал клип | не загружать без `request_clip` |
| 409 | `clip_already_stored` | для эпизода уже сохранён ДРУГОЙ файл | не повторять: доказательство не заменяется |
| 413 | `clip_too_large` | больше 8 МБ | перекодировать меньше (см. §4) и отправить как новый файл |
| 415 | `unsupported_media_type` | не `video/mp4` / `video/x-msvideo` | исправить Content-Type |
| 422 | `not_mp4`, `truncated_mp4`, `mp4_without_index`, `not_avi`, `truncated_avi`, `empty` | файл не тот или повреждён | исправить запись; преподаватель видит причину и может запросить снова |
| 5xx / сеть | — | временная ошибка | повтор с паузами 1, 2, 4, 8, 16 с (до 5 попыток) **теми же байтами** |

Ошибки в теле: `{"error": {"code": "...", "message_ru": "..."}}`.

## 4. Формат файла и метаданные

* **Контейнер:** MP4 (ISO BMFF): `ftyp` первым блоком, обязательно `moov` (незавершённая запись без `moov`
  отклоняется), желательно `moov` перед `mdat` (faststart: `ffmpeg -movflags +faststart`) — воспроизведение
  начинается быстрее; перемотка работает в любом случае (сервер отдаёт HTTP Range).
* **Кодек видео:** H.264 (`avc1`) — рекомендуется: воспроизводится в Edge/Chrome на компьютере преподавателя.
  VP9 (`vp09`) и AV1 (`av01`) в MP4 тоже воспроизводятся. MPEG-4 Part 2 (`mp4v`), HEVC и любой AVI
  принимаются и хранятся, но браузер их не показывает — преподавателю будет предложено «Скачать клип».
* **Звук:** не включать (протокол v1 не записывает звук на диск).
* **Интервал:** 5 с до и 5 с после `t_start_wall` эпизода (§5), т. е. ≈10 с.
* **Размер:** ≤ 8 МБ (8 388 608 байт). Ориентир: 640×480, 10–15 кадров/с, H.264 CRF≈28 → 1–3 МБ на 10 с.
* **Привязка:** студент определяется по `resume_token`, сессия класса — по сессии сервера, эпизод — по
  `incident_id` в URL. Отдельных полей метаданных в теле нет. Сервер сам вычисляет SHA-256, кодек,
  длительность и размер.
* **Тестовые записи:** заголовок `X-Qorgau-Clip-Source: test` (или `synthetic` для синтетической сессии) и
  надпись в кадре (пример: `classreview/testclips.py` — «TEST CLIP - SYNTHETIC - NOT A STUDENT RECORDING»).
  Преподаватель видит пометку «ТЕСТОВЫЙ КЛИП: не запись реального студента». Не выдавать тестовые записи
  за реальные.
* **Приватность:** после ответа 201/200 удалить локальный временный файл; клип не хранится у студента дольше,
  чем нужно для отправки.

## 5. Проверка против DEV-стенда

```bash
cd proctoring
python -m classreview.devserver --pin 123456 --data-dir /tmp/qorgau-class-dev     # печатает PIN
# в браузере http://127.0.0.1:8765/ → PIN → «Начать сессию класса» → код подключения
python -m classreview.examples.fake_student --code <код>                            # синтетический студент
```
Затем в панели: студент → эпизод → «Запросить клип» → «Клип загружается…» → плеер с перемоткой.
