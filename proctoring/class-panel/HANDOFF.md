Ветка: `codex/proctor-T02` (отдельная, разрешена пользователем). Baseline: `65c8c17b5c8d9d861e6099ff260826a2a8a47041`
(`codex/proctor-integration`, «Class protocol qorgau.class.v1 and owners for class server / student uplink»).
Контракт: `proctoring/contracts/class/PROTOCOL_v1.md` — **qorgau.class.v1, заморожен 8 октября 2026 14:45**.
Рабочая папка: `proctoring/class-panel/` (свободна, в OWNERSHIP не закреплена). Ничего вне неё не менялось.

Baseline T01 (общий API-клиент, контракт риска, точки расширения) **не опубликован**: в репозитории нет ни ветки, ни PR,

## Что работает
* Адаптивная сетка карточек (2/30/100), фиксированная высота, без «прыжков»: порядок меняется раз в 4 с, при смене зоны —
  не чаще раза в 1,5 с, по действию преподавателя — сразу; «Закрепить порядок» полностью замораживает порядок.
  Новое событие подсвечивает карточку на месте.
* Карточка: имя/псевдоним, номер компьютера, превью (только то, что пришло; старое — серым с подписью «устарело»),
  связь, камера (неизвестное = «нет данных», устаревшее = «устарело»), этап экзамена, число эпизодов и «без решения»
  (если сервер передаёт), время последнего события, «экран заблокирован»/«микрофон включён» — только если `locked`/`mic_active`
  пришли как `true`.
* Статусы: зелёный «Без замечаний», оранжевый (`yellow`) «Требует внимания», красный «Проверить в первую очередь»,
  серый «Недостаточно данных» — формулировки A05 `zone-rule-1`. Цвет всегда вместе с формой значка (круг-галочка,
  треугольник, восьмиугольник, пунктирный круг) и текстом. Серый — отсутствие данных: нет зоны, нет статуса > 10 с,
  камера ≠ ok, нет связи, нет связи панели с сервером (протокол §4). Своей формулы риска нет: зона берётся из данных.
* Очередь «Требуют внимания» — отдельная колонка; причины только из данных (зона red/yellow, нет связи во время экзамена,
  камера, серый во время экзамена) + первая причина источника; «Просмотрено» прячет до нового события. Без связи с сервером
  очередь честно пустая с объяснением.
* Фильтры по статусам (с числами), фильтр связи, поиск по имени/компьютеру/id, сортировка (по приоритету проверки —
  порядок протокола red → yellow → grey → green; по последнему событию; по имени; по номеру компьютера — естественный порядок).
* Счётчики: студентов, на связи, без связи (и «связь неизвестна»); без связи с сервером — «—», а не старые цифры.
* Карточка студента (диалог): зона с причинами, связь, последний статус, камера, наблюдение, этап, эпизоды по приоритетам,
  без решения, экран, микрофон, превью; слоты «История» (встроенный модуль эпизодов, только просмотр), «Команды», «Аудиосвязь»
  (места для модулей через `window.QorgauClassPanel.registerStudentModule`).
* Состояния: загрузка, пустой класс, ошибка сервера с повтором, потеря и восстановление связи (баннер, все карточки серые,
  счётчики «—», автоматический повтор с backoff 1→15 с, пересинхронизация списка), 401 (нужен вход), 403 (только ПК преподавателя).
* Доступность: русский интерфейс; вся работа с клавиатуры (стрелки/Home/End по карточкам, Enter — открыть, Esc — закрыть
  с возвратом фокуса, ловушка фокуса в диалоге, «/» — поиск, ссылка «К карточкам»); озвучивание новых записей очереди не чаще
  раза в 3 с без потери сообщений; `prefers-reduced-motion` отключает анимации.

## Что использует fixtures / DEMO
* **DEMO-адаптер** (`src/adapters/demo.js`) — всё: студенты, статусы, эпизоды, превью (абстрактные рисунки с водяным знаком DEMO),
  отключения, «сервер». Включён по умолчанию в `config.json` для самостоятельного запуска. Помечен полосой, бейджем, в карточке.
* **REAL-адаптер** (`src/adapters/real.js`) — реальные данные только от сервера класса C1. Против настоящего C1 **не проверен**
  (сервера ещё нет); проверен на mock-ответах контрактных путей (Playwright route) и unit-тестами с поддельными fetch/WebSocket.

## Как открыть
```bash
node proctoring/class-panel/serve.mjs              # http://127.0.0.1:8790/ (DEMO, 30), ?students=2|100, ?rate=busy
node proctoring/class-panel/serve.mjs --upstream http://127.0.0.1:8765   # + ?adapter=real (проксируются только /api/teacher/*, /ws/teacher)
```

## Точка подключения к C1 (для координатора)
1. C1 отдаёт содержимое `proctoring/class-panel/` как статические файлы по `/` (протокол §1: «панель преподавателя … отдаёт
   сервер») — `index.html`, `styles.css`, `src/**`, `config.json` с `{"adapter": "real"}`. Тот же origin → cookie
   преподавателя (HttpOnly, SameSite=Strict) работает, панель сама не отправляет PIN/токены.
2. Заголовки от C1: CSP как в `index.html` + `frame-ancestors 'none'` (в meta не работает), `X-Content-Type-Options: nosniff`.
3. Модули истории/команд/аудио подключаются скриптом C1 через `window.QorgauClassPanelModules = [...]` (до загрузки)
   или `window.QorgauClassPanel.registerStudentModule(...)`.

## Используемые поля qorgau.class.v1
Карточка: поля `status` (§3.1) — `exam_state, camera, monitoring, zone, zone_reasons_ru, incidents_total,
incidents_by_priority, locked, mic_active` + `student_id, computer_name, student_label` (из `hello`). Поток `/ws/teacher`:
`student_update` (карточка в `student` или полями сообщения), `incident` (§3.1), `preview` (`student_id, jpeg_b64 ≤ 30 КБ,
frame_wall`), `ack` (игнорируется панелью — для модуля команд). Неизвестный `type` игнорируется (§3).

## Запросы на общие изменения (C1 / A01) — сами не вносились
1. **Схема карточки `GET /api/teacher/students` и сообщений `/ws/teacher` не зафиксирована в v1.** Панель ожидает массив
   карточек (или `{students: [...]}`) с полями `status` + идентичностью. Просьба C1 добавить в карточку:
   `connected` (bool, по ping/pong §3.2), `last_status_at` (ISO), `last_event_at` (ISO), `incidents_unreviewed`
   (эпизоды без решения преподавателя). Без них панель показывает «нет данных»/вычисляет связь по времени получения.
2. **Вход преподавателя:** v1 описывает PIN → cookie, но не адрес входа. Нужна страница/эндпоинт C1; панель при 401
   показывает понятное сообщение и ничего не придумывает.
3. **Эпизоды:** формат `GET /api/teacher/students/{id}/incidents` (массив или `{incidents}`) и поле `decision` в эпизоде,
   чтобы история показывала решения.
4. **Коды закрытия `/ws/teacher`** при отсутствии авторизации (панель понимает 4401/1008 как «нужен вход»).
5. **OWNERSHIP:** закрепить `proctoring/class-panel/` за T02 (сейчас путь свободен и ничей).
6. **Точка расширения:** если T01 опубликует свою, адаптировать `src/extensions.js` (сейчас локальный реестр).
7. **Нагрузка превью на 100 студентах:** 100 × 1 превью/2 с ≈ 50 JPEG/с (до ~1,5 МБ/с) в панель. Панель обновляет
   картинки только у видимых карточек и умеет «Превью: выкл.», но сервер стоит ограничивать (протокол §7: 100 — цель, не проверено).

## Проверки (Linux-контейнер, Node 22.22, headless Chromium через Playwright 1.56 — не на ПК преподавателя)
| Команда (из `proctoring/class-panel`) | Результат |
|---|---|
| `node --test tests/unit/*.test.mjs` | 23/23 PASS |
| `node <repo>/proctoring/desktop/node_modules/typescript/bin/tsc -p tsconfig.json` (checkJs, strict) | PASS |
| `node tests/e2e/panel.e2e.mjs <out>` | 60/60 PASS |

**Измерено** (DEMO-данные, headless Chromium, 1366×768): на 100 карточках отрисовка одного обновления — среднее 1,6 мс,
p95 3,0 мс, максимум 3,0 мс за 10 с; длинных задач > 50 мс — 0; ~4100 DOM-узлов; при частых событиях порядок карточек менялся
6 раз за 10 с при 27 обновлениях. До оптимизации перестановки (FLIP по всем 100 карточкам) было p95 ≈ 47 мс и 5 длинных задач
за 10 с — исправлено (анимация только видимых, минимальные перемещения DOM).
**Не измерено / предположения:** реальный C1 и сеть класса, настоящие JPEG-превью от 100 студентов, Windows/слабый ПК
преподавателя, экранный диктор (NVDA/JAWS — нужна ручная проверка), длительная работа (часы).
