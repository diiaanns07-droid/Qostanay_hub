# Qorgau Exam
## Локальный помощник преподавателя на онлайн-тесте

Во время экзамена преподавателю нужно видеть значимые эпизоды, их контекст и пробелы в наблюдении.

Проверка каждого видеопотока вручную отнимает внимание от самого экзамена.

Кейс №3 · Qostanai Industry Hackathon · 8 октября 2026

# Один экзамен, общий журнал событий

Qorgau Exam объединяет наблюдения камеры и события экзаменационной среды для последующей проверки преподавателем.

| Этап | Действие |
| --- | --- |
| До экзамена | Проверка камеры и моделей, калибровка |
| Во время | Телефон, ориентиры лица, попытки выхода из среды |
| После | Эпизод, доказательства, решение преподавателя, отчёт |

Новый сценарий: зоны внимания помогают выбрать порядок просмотра сессий. Решение всегда принимает человек.

# Зоны внимания преподавателя

МАКЕТ · вымышленные сессии · функция ожидает интеграции

| Сессия | Зона и значение | Причина | Эпизоды / проверка |
| --- | --- | --- | --- |
| Демо-03 | ! red: Проверить в первую очередь | Телефон у экрана: 00:41, 7 с | 1 / ожидает |
| Демо-02 | ~ yellow: Требует внимания | Взгляд вне зоны: 01:10, 5 с | 1 / ожидает |
| Демо-04 | ? grey: Недостаточно данных | Покрытие наблюдения 65% | 0 / нет решения |
| Демо-01 | + green: Без замечаний | Нет эпизодов, покрытие 100% | 0 / нет решения |

Цвет дополняют символ и текст. Преподаватель открывает доказательства и принимает решение рядом с зоной.

zone-rule-1: high ≥ 1 или medium ≥ 3 = red; иначе medium ≥ 1 или low ≥ 3 = yellow; иначе покрытие < 80% = grey; иначе green. Пороги пока являются гипотезой.

# Объяснимый эпизод и решение

Пример макета: «Телефон направлен на экран: 00:41, 7 с».

| Что видит преподаватель | Зачем это нужно |
| --- | --- |
| Время, длительность, причина | Восстановить контекст события |
| Кадр, если сохранение включено | Сопоставить сигнал с доказательством |
| LIVE / REPLAY / SYNTHETIC | Понимать происхождение наблюдения |
| Версия модели и правила | Воспроизвести результат проверки |

Решение преподавателя хранится отдельно и не меняет рассчитанную зону. Направление камеры телефона и момент снимка нельзя гарантировать по одной веб-камере.

# Данные остаются на ноутбуке

- Обработка кадров и хранение событий предусмотрены локально.
- Демозаписи добровольцев, веса, токены и локальные базы не входят в Git.
- Снимки включаются явно. Для журнала не требуется полная видеозапись.
- Доступ к локальному API проверяется. Публикация отчёта требует отдельного решения оператора.

Полная проверка отсутствия внешней сети, удаления данных и восстановления после сбоя остаётся задачей на кандидате A01.

# Внедрение и ожидаемый эффект

Преподаватель начинает просмотр с сессий red, затем yellow, grey и green. Общая сводка помогает распределить внимание.

Сегодня целевой объём сводки ограничен сессиями одного компьютера. Импорт JSON с других ноутбуков включим только после проверки.

Для пилота нужны Windows-ноутбук с камерой, заранее подготовленные модели, калибровка и проверенный безопасный выход.

Эффект измерим в пилоте: время разбора сессии, доля эпизодов с достаточными доказательствами и число ложных тревог. Подтверждённых процентов экономии пока нет.

# Границы прототипа

- Общий кандидат ещё не прошёл LIVE-проверку на ноутбуке капитана.
- Точность и производительность полной связки пока не измерены.
- Очки, освещение и ракурс влияют на наблюдения. Краткий взгляд вниз может быть обычным чтением.
- OS-блокировки Alt+Tab, Win и PrtScn остаются пробелом опубликованного shell.
- При пробелах в данных сводка сохраняет информацию о покрытии. Red и yellow имеют приоритет над grey по правилу.

Зоны, сетевой сбор и импорт отчётов не объявлены работающими функциями этой версии. Условия AGPL-3.0 для YOLO учитываются перед распространением.
