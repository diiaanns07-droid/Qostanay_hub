## 1. Что это за продукт

**Adal** (каз. «честный») — локальная система прокторинга для онлайн-тестов в вузе. Работает на ноутбуке или ПК студента **без интернета** после подготовки. Одновременно выполняет три требования кейса:
1. **Телефон:** телефон в кадре, телефон поднят к экрану, возможная съёмка экрана — YOLO11n (COCO «cell phone»).
2. **Взгляд и лица:** направление взгляда отдельно от поворота головы, долгий взгляд вниз и в сторону, нет человека, второе лицо — MediaPipe Face Landmarker, личная калибровка, сглаживание OneEuro.
3. **Защита среды:** блокировка Win, Alt+Tab и PrtScn на уровне Windows (собственный помощник с low-level hook), Ctrl+C/V/X, вкладки, новые окна, навигация, DevTools; возврат фокуса при уходе в чужое окно; детекция RustDesk, AnyDesk и т.п., второго монитора, виртуальной машины.

**Сверх ТЗ:**
- объяснимые эпизоды и **зоны** для преподавателя (зелёная / жёлтая (оранжевая в UI) / красная / серая);
- отчёт HTML/JSON;
- сверка «тот же человек, что в начале»;
- звук: возможная речь и шёпот рядом (Silero VAD + YAMNet), без записи звука;
- книги и второй экран в кадре;
- осмотр рабочего места (в работе);
- **режим класса**: сервер преподавателя в LAN, карточки студентов, блокировка с причиной, клипы эпизодов, аудиосвязь (в работе);
- режим «экзамен-сайт»: сайт теста вуза (например, Moodle) открывается внутри Adal по белому списку адресов.

Позиционирование для жюри: «Локальная альтернатива коммерческим облачным сервисам прокторинга для вузов Казахстана: без облака и постоянной записи, с настоящей блокировкой Windows, объяснимые эпизоды, решение принимает преподаватель».

## 2. Архитектура (кратко)

```
Камера → A02 capture (один владелец камеры, кольцевой буфер, клипы)
       → A03 phone (YOLO11n ONNX: телефон, книга, ноутбук/tv) ─┐
       → A04 attention (MediaPipe: лица, поза, взгляд, калибровка) ├→ A05 fusion: эпизоды, приоритеты, зоны
       → A13 identity (YuNet+SFace: тот же человек) ───────────┘        ↓
Микрофон → A14 audio (Silero VAD + YAMNet, только числа) ─────→ A08 evidence: SQLite, отчёт HTML/JSON
Electron оболочка A06 (киоск, блокировки, qorgau_guard.py helper) ↔ backend (FastAPI, loopback, токен)
Интерфейс студента/преподавателя A07 (React)
Режим класса: C2 uplink (студент) ↔ сервер T01 (classroom/) + панель T02 + клипы T03 + команды T04 + аудио T05
```

## 7. Известные ограничения (говорить честно)
- Взгляд — приблизительная оценка, нужна калибровка. Поворот головы в профиль система видит как «лицо не видно».
- «Возможная съёмка» не доказывает снимок. Факт съёмки по одной веб-камере не установить.
- Ctrl+Alt+Del не блокируется никем: фиксируем, а полная блокировка — политиками Windows вуза.
- Звук: только «есть речь или нет», шёпот в тишине не проверен вживую. Сверка лица — не установление личности, без базы лиц.
- Наушники-вкладыши и AirPods по веб-камере не обнаруживаются.
- Режим класса: проверен на одном ноутбуке; 3 компьютера и 100 студентов — цель, не проверено. Клипы MJPG в браузере — скачать (MP4 в работе).
- Пороги зон — гипотезы для пилота.
