# T05 — аудиосвязь (STATUS)

Роль: T05, серверная сигнализация аудиосессий и аудиомодуль пульта преподавателя.
Ветка: `codex/proctor-T05` (отдельная; назначенная платформой ветка этой сессии уже содержит работу A07, роли не смешиваю).
Baseline: `65c8c17b5c8d9d861e6099ff260826a2a8a47041` (`codex/proctor-integration`, «Class protocol qorgau.class.v1 …»).
**Baseline T01 не опубликован** (нет ни ветки, ни путей; T02 столкнулся с тем же и стартовал от того же коммита).
Поэтому точки подключения и контракт оформлены как предложение T05; общие файлы, контракты, зависимости, студенческое
приложение и CV не менялись. Рабочая папка `proctoring/class-audio/` (свободна, в OWNERSHIP не закреплена).

## Решение
WebRTC точка-точка в LAN (Opus, DTLS-SRTP, `iceServers: []`), сигнализация через сервер класса; сервер звук не видит
и не записывает. Обоснование и альтернативы — `PROTOCOL_AUDIO.md` §1.

## Что сделано
* `PROTOCOL_AUDIO.md` — `qorgau.class.audio.v1`, аддитивно к `qorgau.class.v1` §6: запрос (`audio_request`),
  подтверждение (`ack` на `audio_start`, только после показа индикатора), фактическое начало (`connected` по отчёту
  медиа), изменение (`audio_update`), остановка (`audio_stop`), обрыв (`student_disconnected`, `network_lost`,
  `teacher_disconnected`, `teacher_auth_lost`, `server_shutdown`), коды ошибок, таймауты.
* `AudioHub` (Python, без новых зависимостей): одна активная сессия на преподавателя и на студента; пересылка только
  между двумя участниками активной сессии (чужие/поддельные `audio_signal`/`audio_media`/`ack` отбрасываются,
  отправителю `session_mismatch`); студент не может начать сессию; белый список полей при пересылке; таймауты
  accept 15 с / connect 20 с; любое завершение → студенту `audio_stop`, преподавателю `audio_state ended`.
* DEV-сервер сигнализации (не C1): PIN → HttpOnly SameSite=Strict cookie, 5 ошибок → 30 с; маршруты преподавателя
  только с loopback + проверка Origin; `/ws/student` по v1 (hello/welcome/resume_token/ping 5 с/15 с); выход
  преподавателя = `teacher_auth_lost` до закрытия сокетов; CSP/nosniff/Permissions-Policy; опциональный TLS;
  опционально отдаёт панель T02 с того же origin и подключает модуль одной строкой (как должен C1).
* Пульт: контроллер `TeacherAudio` — «Слушаю» только при `connected` + растущих входящих RTP-пакетах + `mic_live`
  от студента (инвариант проверяется на каждом изменении состояния); «Говорю» — по исходящим пакетам; ICE restart при
  кратком обрыве, 10 с → `network_lost`; понятные ошибки микрофона с подсказкой; «Подключиться снова».
  UI: «Слушать» / «Говорить» / «Завершить связь», для другого студента — «линия занята», без кнопок подключения.
  Слот «Аудиосвязь» панели T02 (`class-panel-module.js`) и отдельная страница.
* Эталон студенческой стороны `StudentAudioEndpoint` (индикаторы до `ack`, микрофон только при «слушать», fail closed)
  и **ТЕСТОВЫЙ PEER** (красная маркировка, имитация отказа/отсутствия устройства/обрыва, resume).
* Документы: `README.md`, `STUDENT_INTEGRATION.md` (для разработчика приложения студента), `LAN.md`.

| Проверка | Результат |
|---|---|
| `pytest -q proctoring/class-audio/server/tests` | **24 passed** (хаб 16, сервер на настоящем uvicorn 8) |
| `tsc -p proctoring/class-audio/tsconfig.json` (checkJs, strict) | PASS |
| `node proctoring/class-audio/tests/e2e/audio.e2e.mjs` | **33/33 PASS** |

e2e (настоящий WebRTC между страницами, сервер — отдельный процесс):
слушать (входящий уровень звука > 0 от тестового тона) · «Слушаю» не раньше соединения (последовательность статусов
записана) · говорить (у студента «Говорит преподаватель», звук реально приходит) · выключить «слушать» → трек
микрофона студента остановлен, разговор продолжается · включить снова (перенегоциация) · второй студент: панель
«занято», сырой `audio_request` → `teacher_busy`, поддельные сигнал/стоп от студента B для сессии A отброшены, у B
микрофон не запрашивался · «Завершить» → у студента трек `ended`, peer закрыт, индикаторы сняты; у преподавателя
peer закрыт, микрофон отпущен · обрыв связи студента → микрофон студента выключен сразу, у преподавателя «студент
потерял связь» · восстановление по `resume_token` → «Подключиться снова» → снова «Слушаю» · закрытие страницы
студента → сессия завершена · выход преподавателя → у студента трек `ended` · **настоящий** отказ в разрешении
(`NotAllowedError`, полный Chromium с `--deny-permission-prompts`) → `mic_denied` · **настоящее** отсутствие
устройства (`NotFoundError`, в контейнере нет звуковых устройств) → `mic_not_found` · отказ микрофона у преподавателя
→ сообщение + подсказка, студенту ничего не отправлено · пульт с не-loopback адреса → 403 · тестовый peer по
`http://192.0.2.2` (не secure context) → `insecure_context` · остановка сервера → у студента трек `ended`, у
преподавателя `ended` · HTTPS/WSS на `https://192.0.2.2` с тестовым CA (доверие только в отдельной NSS-базе
браузера) → «Слушаю» · панель T02 (`codex/proctor-T02` @ `1363e3c`, REAL-адаптер, тот же origin) → слот
«Аудиосвязь» → «Слушаю» → «Завершить» → трек студента `ended`.

Найдено и исправлено по ходу: «Слушаю» на долю секунды оставалось после выключения микрофона у студента (теперь
инвариант); в небезопасном контексте нет `crypto.randomUUID` (тестовый peer падал до подключения).
Особенность песочницы: Chromium шёл к не-loopback адресу через исходящий прокси, который отвечал 403 на `ws://`;
в тестах `--proxy-server=direct://` (на ПК класса прокси нет; это не обход защиты браузера).

## НЕ проверено
* **Интеграция с приложением студента** (Electron + uplink C2) — не делалась и не заявляется.
* Два реальных компьютера, LAN/Wi-Fi, изоляция клиентов, брандмауэр Windows, mDNS — всё проверено только на одном хосте.
* Сервер класса C1 (его нет) — проверен DEV-сервер; `AudioHub` рассчитан на встраивание.
* Восстановление медиаканала ICE restart при живой сигнализации (код есть; на одном хосте обрыв UDP не воспроизвести).
* Реальные микрофоны/гарнитуры, эхо, качество звука, задержка (тестовый тон Chromium); Firefox/Safari; Windows.
* Экранный диктор (NVDA/JAWS); долгие сессии.

## Требования для LAN (кратко, подробно — LAN.md)
одна подсеть без изоляции клиентов; входящий UDP для браузера преподавателя и приложения студента, TCP 8765 на ПК
преподавателя; пульт только на ПК преподавателя (localhost = secure context); приложение студента — secure origin
(`qorgau://app`) с разрешённым аудио; сигнализация студентов по `wss://` с закреплённым сертификатом; без STUN/TURN —
через NAT/VLAN не работает.
