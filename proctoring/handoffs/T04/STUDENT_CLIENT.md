# Команды преподавателя: точная инструкция для студенческого клиента (T04 → разработчик студенческой стороны)

Кому: разработчику студенческого клиента (uplink C2 + оболочка студента). Windows-блокировки, экран блокировки и
оболочку реализует он; T04 отвечает за сервер: выдачу команд, их сроки, учёт подтверждений и показ преподавателю.
Протокол: `qorgau.class.v1` (`contracts/class/PROTOCOL_v1.md`) плюс **аддитивные** поля из запроса T04 → T01
(`handoffs/T04/DEPENDENCIES.txt`, R2). Пока T01 их не утвердил, они необязательны: сервер работает и с простым v1-клиентом,
но тогда преподаватель видит меньше (нет «выполняется», нет смены политики на лету).

Эталон поведения клиента — симулятор T04 `backend/proctor_classctl/simulator.py` (`SimulatedClass._receive/_complete/_finish`).
Он **только** имитирует ответы и ничего не блокирует; реальный клиент должен вести себя так же по протоколу.

## 1. Главные правила (обязательно)
1. **Одна команда — одно выполнение.** `command_id` — ключ идемпотентности. Повторная доставка того же `command_id`
   (после переподключения сервер повторяет неподтверждённые команды с тем же id) **не выполняется снова**: клиент повторно
   отправляет сохранённый `ack`. Хранилище выполненных команд переживает перезапуск приложения (до конца сессии экзамена).
2. **Просроченная команда не выполняется никогда.** Перед выполнением и ещё раз перед необратимым шагом проверить срок:
   команда просрочена, если **любое** из условий:
   * `monotonic_now − received_monotonic > ttl_ms` (время, оставшееся на момент доставки; не зависит от часов ПК);
   * `local_now + clock_offset > expires_at`, где `clock_offset = welcome.server_time − local_time_at_welcome`.
   Просроченная команда → `ack {ok:false, code:"expired"}` без выполнения. Так блокировка, полученная после долгого
   отключения или застрявшая в очереди клиента, не сработает неожиданно.
3. **`ack {ok:true}` только по факту.** Для `lock` — когда экран блокировки реально показан поверх окна экзамена; для
   `unlock` — когда он реально снят; для `start_exam` — когда экзамен реально открыт и ограничения включены; для
   `apply_policy` — когда новые правила действуют. Ошибка выполнения → `ok:false` с кодом и понятным `error_ru`.
   Сервер показывает «выполнено» и «заблокирован» только по `ack` и `status`, а не потому, что принял запрос.
4. **Ровно один `ack` на команду** (правило v1). Промежуточное состояние сообщается отдельным сообщением
   `command_progress`, это не `ack`.
5. **Честные возможности.** В `hello.capabilities` объявлять только то, что реально реализовано и проверено на этой машине.
   Чего нет в списке — сервер показывает преподавателю как недоступное и не отправляет.
6. **`status.locked` — правда о текущем экране.** Отправлять свежий `status` сразу после любого изменения (блокировка,
   разблокировка, старт, финиш) и раз в 2 с (v1). После переподключения первым делом — свежий `status`.

## 2. Подключение
`hello` (v1) + аддитивный блок `capabilities`:
```json
{"type":"hello","v":1,"msg_id":"…","sent_at":"2026-10-09T09:00:00.000Z","protocol":"qorgau.class.v1",
 "join_code":"123456","computer_name":"PC-12","student_label":"Иванов","app_version":"0.4.0",
 "capabilities":{"commands":["start_exam","finish_exam","lock","unlock","apply_policy"],
                 "modes":["url"],"command_progress":true,"command_expiry":true,"site_timer_pause":false}}
```
* `commands` — только поддерживаемые виды команд. `modes`: `"url"` (внешний сайт в окне клиента) и/или `"app"`
  (отдельная программа) — `"app"` объявлять, только если клиент умеет ограничивать набор программ.
* `command_progress: true` — клиент шлёт `command_progress`; `command_expiry: true` — клиент выполняет правило 1.2.
* `site_timer_pause` — всегда `false`: интеграции с сайтами нет, наша блокировка **не останавливает таймер сайта**.
* Без блока `capabilities` сервер считает клиента простым v1: доступны только `start_exam`, `finish_exam`, `lock`, `unlock`.

`welcome.exam` содержит политику, назначенную этому студенту:
```json
{"exam_id":"exam-…","title":"Физика","policy_id":"pol-…","version":3,"name":"Основная","mode":"url",
 "start_url":"https://exam.example.kz/test/1","allowed_urls":["https://exam.example.kz/*","https://accounts.google.com/*"],
 "auth_domains":["https://accounts.google.com/*"],"allowed_apps":[],"instructions_ru":"…","site_timer_control":"none"}
```
Запомнить политику и `clock_offset`. Применять её при `start_exam`.

## 3. Приём команды — алгоритм
Сообщение сервера:
```json
{"type":"command","v":1,"msg_id":"…","sent_at":"2026-10-09T09:05:00.000Z","command_id":"cmd-3f…","kind":"lock",
 "payload":{"reason_ru":"Проверка документов"},"issued_at":"2026-10-09T09:05:00.000Z",
 "expires_at":"2026-10-09T09:07:00.000Z","ttl_ms":120000,"attempt":1}
```
```
on command(msg):
    if msg.command_id in done_store:            # повторная доставка
        send(done_store[msg.command_id]); return # тот же ack, без выполнения
    received = monotonic()
    if expired(msg, received):  return finish(msg, ok=false, code="expired")
    if msg.kind not in my_capabilities.commands:  return finish(msg, ok=false, code="unsupported")
    if not valid(msg.kind, msg.payload):          return finish(msg, ok=false, code="invalid")
    if busy_with_same_kind(): ...                 # выполнять команды строго по порядку получения
    send command_progress {command_id, state:"received"}      # если объявлен command_progress
    prepare(msg)                                  # обратимая подготовка
    if expired(msg, received):  return finish(msg, ok=false, code="expired")   # повторная проверка
    send command_progress {command_id, state:"executing"}
    try:   result = execute(msg)                  # реальное действие оболочки
    except E: return finish(msg, ok=false, code="failed", error_ru=<понятная причина>)
    finish(msg, ok=true, result=result)

finish(msg, ok, code=None, error_ru=None, result=None):
    ack = {type:"ack", command_id, ok, code?, error_ru?, result:{locked, exam_state, policy_id?, policy_version?},
           executed_at: <ISO UTC> if ok}
    done_store[command_id] = ack      # СНАЧАЛА сохранить (fsync), потом отправить
    send_or_queue(ack)                # нет связи -> очередь v1 (до 1000 записей), отправка по порядку после переподключения
    send(status)                      # свежий статус после изменения
```
Коды `ack.code`: `expired` (срок истёк, не выполнялась), `unsupported` (не поддерживается), `invalid` (неверные параметры
или устаревшая версия политики), `duplicate` (только если повтор нельзя ответить сохранённым ack), `failed` (пыталась и не
смогла), `busy` (временно невозможно, например, оболочка перезапускается — сервер покажет «ошибка»; преподаватель повторит).

## 4. Смысл команд
| kind | payload | Что сделать | `ack ok:true` когда | `status` после |
|---|---|---|---|---|
| `start_exam` | `{}` | открыть экзамен по текущей политике: `url` — `start_url` в окне экзамена, переходы только по `allowed_urls`; `app` — разрешённые программы; включить ограничения (оболочка) и наблюдение | экзамен открыт, ограничения включены | `exam_state:"running"` |
| `lock` | `{reason_ru}` 1–200 символов | полноэкранный экран блокировки поверх экзамена с причиной; камера и наблюдение продолжают работать; **таймер внешнего сайта не останавливается** — не писать студенту обратное | экран блокировки показан | `locked:true` |
| `unlock` | `{}` | снять экран блокировки (ограничения экзамена остаются) | экран снят | `locked:false` |
| `finish_exam` | `{}` | завершить сессию, снять ограничения и блокировку | сессия завершена | `exam_state:"finished"`, `locked:false` |
| `apply_policy` | `{policy_id, version, name, mode, start_url, allowed_urls, auth_domains, allowed_apps, instructions_ru, site_timer_control}` | заменить активную политику; если экзамен идёт — сразу применить новые правила переходов/программ. Версия ниже уже применённой для того же `policy_id` → `invalid` | новые правила действуют | (`result.policy_id/policy_version`) |

`lock` и `unlock` задают состояние: если пришли обе, действует последняя по порядку получения. Повторная `lock`, когда экран
уже показан, — успех с тем же результатом (обновить причину).

## 5. Сопоставление адресов (`allowed_urls`)
Шаблон: `<scheme>://<host>[:<port>]<path-prefix>*`. Адрес разрешён, если есть шаблон, у которого:
* схема совпадает точно (`https` ≠ `http`);
* хост (в нижнем регистре, IDNA/punycode, без завершающей точки) равен хосту шаблона, а для `*.domain` — равен `domain`
  **или** оканчивается на `.domain` (не просто «содержит»: `evil-domain.kz` не подходит);
* порт совпадает (по умолчанию 443 для https, 80 для http);
* путь начинается с префикса шаблона, либо `путь + "/"` равен префиксу (`/test/42/*` разрешает `/test/42`, но не `/test/420`).
Логин/пароль в адресе, схемы кроме http(s) (`javascript:`, `file:`, `data:`) — всегда запрещены. Эталонная функция:
`policies.match_url`, тесты: `tests/test_exams_access.py::test_url_matching_reference`. Домены входа (`auth_domains`)
уже включены в `allowed_urls`; отдельный список нужен только для объяснений.

## 6. Обрыв связи
* Неотправленные `ack` — в очередь v1, после переподключения отправить по порядку (сервер отметит «подтверждено после
  восстановления связи»). `status` и `preview` в очередь не кладутся.
* Сервер может повторить неподтверждённую команду с тем же `command_id` (поле `attempt` растёт) — правило 1.1.
* Команды, полученные, но не начатые до обрыва, после переподключения выполнять **только** если они не просрочены (правило 1.2).

## 7. Проверка соответствия (что проверит T04/QA)
| Проверка | Ожидание |
|---|---|
| `lock`, затем обрыв на 3 мин, переподключение | старая `lock` не выполняется (`expired` на сервере или `ack code:expired`), `status.locked:false` |
| повторная доставка того же `command_id` | одно выполнение, повторный `ack` с тем же содержимым |
| `lock` выполнена, обрыв до отправки `ack` | `ack` из очереди после переподключения, повторного выполнения нет |
| неподдерживаемая команда | `ack {ok:false, code:"unsupported"}`; лучше — не объявлять её в `capabilities` |
| `lock` с пустой причиной / 201 символ | `ack {ok:false, code:"invalid"}` |
| `status.locked` | совпадает с тем, что видно на экране студента, после каждого изменения и каждые 2 с |
| `apply_policy` со старой версией | `ack {ok:false, code:"invalid"}`, текущая политика не меняется |
