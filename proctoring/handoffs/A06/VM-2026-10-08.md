# A06 — виртуальная машина: advisory preflight

Ветка `codex/proctor-A06-vm`, база `a7cf612068eb0b4732cfe87170ffc3204517de40`.
Checkout `A06-env`. Контракт 1.1 не изменён.

## Поведение

- Перед preflight (также при штатном обновлении capabilities перед start/resume) Electron main
  вызывает native helper `--vm-check`. Только чтение WMI через локальный PowerShell/CIM:
  `Win32_ComputerSystem.Manufacturer/Model`, `Win32_BIOS.Manufacturer/SMBIOSBIOSVersion/Version`.
  Серийные номера, UUID, имена пользователей, содержимое окон и буфера не запрашиваются.
- VMware, VirtualBox/innotek, Hyper-V, QEMU/KVM, Parallels, Xen определяются по строкам этих полей.
  Для Hyper-V требуется именно пара Microsoft Corporation + Virtual Machine: Surface и сам факт
  наличия гипервизора/VBS на физическом хосте не считаются гостевой ВМ.
- Результат `detected` → «Защита среды» WARN:
  **«Экзамен запущен в виртуальной машине (<платформа>)»**. ВМ/VDI не запрещает начать экзамен.
- Ошибка, отказ доступа, неполный ответ, невалидный JSON или таймаут → `unknown`, WARN с текстом
  «Не удалось определить, запущен ли экзамен в виртуальной машине (WMI: unknown)».
  Это неопределённость, не успешная проверка физического устройства. Она также не блокирует старт.
- Успешное чтение без известных сигнатур → `not_detected` («Признаки виртуальной машины не обнаружены»).
  Это эвристика по WMI, не доказательство отсутствия виртуализации: подменённые/неизвестные строки
  или другие платформы могут не определиться.
- Таймаут PowerShell 8 с, внешнего helper 10 с, окна PowerShell скрыты. Запрос не включает hooks,
  enforce, возврат фокуса, изменение настроек или завершение чужих процессов. Новых зависимостей нет.

## Минимальное подключение и контракт

`main/src/environment/vm.ts` использует существующие поля capabilities:
`action=exam_mode_engaged`, `mechanism=native.vm_check.detected|not_detected|unknown`,
`status=detected_only|unverified`, `note_ru`. Флаг `exam_mode_supported` не ослабляется.

Единственная backend-правка — 13 строк в `proctor/session.py::_environment_check`.
Сначала сохраняются существующие FAIL второго монитора/remote access и проверка работоспособной
защиты. Только если основная защита проходит, VM detected/unknown возвращается как WARN,
`required=False`, `message_code=virtual_machine_detected|virtual_machine_unknown`,
`details.vm_state`. Поэтому существующий расчёт `ready` пропускает этот advisory, но обязательные
ошибки не превращаются в предупреждение. Алгоритм `ready`, fusion и контракт не менялись.

При первом успешном включении режима экзамена `ExamGuard` отправляет одно информационное событие
через штатный EnvironmentEventQueue: `action=exam_mode_engaged`, `enforcement=allowed`,
`scope=os_session`, `mechanism=native.vm_check.<state>`, `detail.shortcut=<платформа или state>`.
Специального VM action в контракте нет; существующее поле shortcut здесь служит короткой меткой.
Это отдельная запись метаданных рядом со штатной записью включения kiosk, без escape-инцидента.
Повторы engage, пауза/resume и повторная привязка той же сессии не дублируют VM-запись.
Backend также дедуплицирует повтор доставки по client_seq. До старта результат виден в preflight;
журнальная запись отправляется при старте, когда backend принимает environment events.
Дедупликация отправки живёт в экземпляре shell; после полного перезапуска приложения может быть
новая запись для восстановленной сессии (общий существующий протокол не хранит VM-флаг на диске).

## Проверки

- Python native + backend lifecycle: 97 PASS на первом прогоне; добавленный API-roundtrip вместе
  с VM unit-тестами: 24 PASS. Все шесть платформ (включая оба варианта VirtualBox и QEMU/KVM),
  сигнатуры BIOS, физическое железо/Surface, отсутствие полей, ошибки/таймаут WMI.
- Node shell: 106 PASS, 1 существующий Windows skip. Проверены протокол subprocess, unknown при
  отсутствии helper, сохранение display/remote FAIL и одно событие на сессию.
- `npm run typecheck`: contracts/main/renderer PASS; `npm run build:electron`: PASS.
- API-roundtrip на синтетической сессии: capabilities → WARN → ready=true → start → приём
  события → дедупликация повторной доставки → finish. Отдельные backend unit-тесты проверяют
  LIVE required-gate и приоритет hard failures. Реальный экзамен/камера не запускались.
- Read-only LIVE ноутбука 2026-10-08 18:42 (+05): **not_detected**, ASUSTeK COMPUTER INC.,
  ASUS TUF Gaming A15 FA507NU_FA507NU; BIOS American Megatrends International, LLC., FA507NU.316.
  CLI `qorgau_guard.py --vm-check` отдельно вернул тот же результат.
  [Машиночитаемое наблюдение](checks/vm-2026-10-08/laptop.json).
- На настоящих гостевых ВМ LIVE не выполнялся: распознавание платформ проверено заглушками.
  Для приёмки на ВМ: запустить preflight, увидеть платформу/WARN и разрешённый старт;
  после start/pause/resume проверить одну запись `native.vm_check.detected` в журнале сессии.
