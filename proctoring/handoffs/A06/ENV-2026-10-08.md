## 3. Remote-access processes and RDP

`qorgau_guard.py --environment-check` is a short-lived **read-only** mode: no hook is installed.
Win32 Toolhelp snapshot enumerates executable basenames; only exact case-insensitive matches to
rustdesk, anydesk, teamviewer, tv_w32, tv_x64, ultraviewer_desktop, remoting_host, parsecd,
winvnc, tvnserver, rutserv leave the helper. No titles/command lines/full paths are transmitted.
RDP uses `GetSystemMetrics(SM_REMOTESESSION=0x1000)`. This is the requested session flag;
it is not a general detector of every remote-control technology or active connection.

Before preflight/start/resume, current matches produce `native.remote_check.<basename>` capability
items, `exam_mode_supported=false`, and «Закройте <basename>.exe, чтобы начать».
RDP requests ending the remote session. Failed enumeration/helper timeout is unknown and blocks
preflight with an explicit reason; it never silently means no remote software.
The backend preflight adapter additionally recognizes the `native.remote_check.` prefix.

During RUNNING a non-overlapping 5 s scan (plus initial scan) emits an EnvironmentEventIn via the
existing queue: action `foreign_window_foreground`, mechanism `native.remote_access`,
`process_name=<basename>.exe`; `RDP` is a documented logical marker, not an executable.
One event per appearance; absence rearms it. This chosen action is permitted by the unchanged
contract, but this mechanism means process presence, not actual foreground/connection.
It does not trigger the foreground refocus path. Release invalidates in-flight results.

Tests: 47 native/backend tests, 8 focused Node tests, typecheck and Electron build passed.
