# T04 UI — замечания к API (для backend T04 и T01)

Интерфейс в `class-control-ui/` сделан только поверх существующего API `/api/teacher/control/*` и DEV-эндпоинтов
`/sim/*`. Python-код и общие контракты не менялись. Ниже — чего не хватает и как UI обходится сейчас.

| # | Пробел | Как сейчас в UI | Что предлагается |
|---|---|---|---|
| A1 | Нет «кто я» и моей роли в экзамене. `actions[kind].available` учитывает только клиента студента, роль преподавателя не учитывает. | В DEV-режиме роль вычисляется в UI (`effectiveRole`: владелец / `staff` / роль учётной записи из `/sim/info`), как в `access.check()`. На реальном сервере (вход по PIN) роль неизвестна, поэтому кнопки включены, а сервер отвечает 403. UI показывает этот ответ. | `GET /control/me` → `{teacher_id, display_name, role}` или поле `my_role` / `can: {view, edit, command}` в ответе экзамена. |
| A2 | Ошибка проверки списка (`allowed_urls`, `auth_domains`, `allowed_apps`) возвращает `details.field` без номера элемента. | Ошибка выводится под всем списком, а плохое значение видно из `message_ru`. | Добавить `details.index` и `details.value`. |
| A3 | Ошибки проверки FastAPI/pydantic (`extra_forbidden`, `string_too_long`, `max_length` списков) приходят в формате `{"detail":[...]}`, а не `{"error":{...}}`. | `normalizeError()` разбирает оба формата и берёт поле из `loc`. Текст получается общим («слишком длинное значение»). | Обработчик `RequestValidationError` → `{"error":{"code":"validation","message_ru":…,"details":{"field":…}}}`. |
| A4 | В `label_ru` команды время указано в UTC («…при подключении до 10:05:48 UTC»), а остальной UI показывает местное время. | Текст выводится дословно, как требуется. Рядом в карточке студента срок показан по местному времени из `expires_at`. | Отдавать время в label в местном часовом поясе сервера или без времени (UI возьмёт его из `expires_at`). |
| A5 | Нет push-обновлений. | Опрос `GET …/students` раз в 1 с (`?poll_ms=` только для тестов), экзамен раз в 5 с, журнал раз в 2 с при открытой вкладке. | Сообщение `command_update` в `/ws/teacher` (уже записано в DEPENDENCIES R5). |
| A6 | В `GET /exams` нет экзаменов, к которым нет доступа (так и задумано). | «Нет доступа» показывается для экзамена, выбранного ранее (localStorage или `exam_id` из `/sim/info`), по ответу 403 на `GET /exams/{id}`. | Ничего. |
| A7 | Доступность назначения политики (поддерживает ли клиент режим) заранее не сообщается, `actions` есть только для 4 команд. | Ответ «не назначена — …» приходит в результате `POST /assignments` (`unavailable_ru`). | `actions.apply_policy` или `assignable_modes` в виде студента. |
| A8 | Нет списка учётных записей преподавателей для состава экзамена. | Состав (`staff`) вводится как свободный id + роль. | `GET /control/teachers`, когда T01 введёт несколько учётных записей (DEPENDENCIES R4). |
| A9 | Где монтировать UI на сервере класса. `index.html` ссылается на `/ui/styles.css` и `/ui/src/app.js`; в DEV-сервере страница отдаётся на `/`, папка — на `/ui/`. По протоколу v1 `/` — это панель T02. | Работает в DEV-сервере. | T01/C1: отдавать папку на `/ui/`, а страницу — например, на `/control/` (или поменять пути в `index.html`). Модуль для T02 подключается как `<script type="module" src="/ui/t02-module.js">`. |
| A10 | `ttl_s` в API есть, в UI не выводится. | Действуют сроки сервера (`meta.ttl_default_s`). Перед отправкой UI показывает срок и предупреждает, что просроченная команда не выполнится. | Нужно ли преподавателю менять срок — решение продукта; при необходимости добавим поле. |
| A11 | `GET …/students` отдаёт только последние 5 команд. | Полная история загружается в карточке студента через `GET …/commands?student_id=`. | Ничего. |

Учтённые инварианты API (UI на них опирается и проверяет их e2e-тестом):
* `202` на `POST /commands` значит только «принято сервером». «Выполнено» появляется только при `command.group == "done"`.
* Состояние экрана берётся из `lock.label_ru` дословно. Слово «Заблокирован» UI не формирует сам.
* На один щелчок создаётся один `idempotency_key` (UUID). При повторе после сетевой ошибки отправляется то же тело с тем же ключом, и сервер отвечает `created:false`.
* Недоступное действие (`actions[kind].available == false`) показывается отключённой кнопкой с `reason_ru`.
* Пауза таймера внешнего сайта всегда недоступна. Отключённая кнопка с объяснением отделяет её от нашей блокировки.
